# 2026-11-09

## `nonQueryBindings` on `sql-template/no-unsafe-query`

- The upstream rule matches keyword-then-space text with no options. `Select model, ${label}` is lexically a valid SELECT list, so no text match separates that accessibility label from a query; Homer disabled the rule across six whole files to get past 11 such labels.
- `/eslint` now serves the upstream rule with one option naming the object-property and JSX-attribute bindings that never carry SQL. Names come from the consumer, so no framework vocabulary lives here. No option, no change.
- The name counts only when the template reaches the binding as its value, through conditional branches, logical operands, array elements, or an array literal's `.filter(Boolean)` and `.join("literal")`. Call arguments, conditional tests and computed keys stay checked.
- Independent review caught the first version following every method receiver: `[`SELECT ...${id}`].map(executeQuery).join(", ")` bound to a named label reported 0, leaving an executing query unchecked. A method name proves nothing on its own, so only those two calls count, on an array literal, with a global `Boolean` and a string literal argument. Homer's one composed label needs no more. String methods such as `.trim()` stay reported.
- On Homer's client with `accessibilityLabel` named: 11 reports without the option and 0 with it on those six files, 0 across `src`, `app` and `convex`, and real queries in other positions still report.

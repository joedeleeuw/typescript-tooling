# 2026-10-23

## Copied lint rules move from Antidrift to this package

Owner decision: `@joedeleeuw/antidrift` stops carrying lint rules copied from other projects, and this package takes them over. A check that exists in a published, maintained package becomes a dependency that this package turns on, without per-rule proof here. Rules copied from sources with no published package are vendored and maintained here, with packed-consumer proof. One owner per problem: a copied rule that only duplicates a rule this package already enables is neither vendored nor enabled. Version 0.3.0.

Published source: `@rikalabs/oxlint-standards` 0.8.1 (MIT) is a dependency, registered as the `rikalabs` JS plugin. Twelve rules are `error`; `no-unlisted-external-imports` is registered `off` because 6 of 20 sampled reports on four public repositories were real. `no-as-never` is not enabled: the full tier's `typescript/no-unsafe-type-assertion` owns that problem.

Vendored, as the `tooling` plugin in `src/oxlint-plugin`, from Antidrift 048a392: 37 stella rules (Apache-2.0), anti-slop's `no-unknown-type-aliases` (MIT) and Sentry's `no-calling-components-as-functions` (FSL-1.1-Apache-2.0). Four stella rules ship `off`, each measured under half real in 20 sampled reports on four public repositories: `no-physical-properties` 9 (all in apps that ship right-to-left locales), `no-raw-foreground-opacity` 0, `require-fetch-timeout` 5 (12 were in tests) and `require-query-key-factory` 4. Anti-slop's `no-chained-type-assertions` and `no-widen-then-assert` stay behind because the full tier's `typescript/no-unsafe-type-assertion` reports both. Antidrift never shipped Sentry's license text; it now ships in `licenses/` and NOTICE. The package's `license` field still says MIT; that one file stays under the FSL until two years after Sentry released the version Antidrift ported, which Antidrift did not record.

ESLint gains a `restrictedSyntax` entry for async callbacks passed to `forEach`, replacing Antidrift's async-array rule for that method. Async `filter`, `some`, `every` and `find*` callbacks are already reported by `typescript/no-misused-promises` in the full tier. Its `checksVoidReturn` setting stays: turning argument checks on adds 165 reports across opencode, LibreChat and cloudflare/agents, none of them `forEach(async)`.

Findings that changed execution. Every stella rule imported Antidrift's TypeScript `semantic-adapters/kernel/rule-scope.ts`, which Antidrift's build compiles; Node refuses to strip types under `node_modules` (`ERR_UNSUPPORTED_NODE_MODULES_TYPE_STRIPPING`, checked on 24.22.1) and this package ships source, so the helper ships as JavaScript, equal to Node's type-stripped original after formatting. The stella rule files change only in that import line. The Sentry rule's helpers ship as one module of the 21 declarations it reaches, each equal to its stripped original once `AST_NODE_TYPES` members become their identical string values. `syntax.js` and `dictionary-types.js` are imported by none of the vendored rules, so no Rika Labs code is vendored; that package is only a dependency.

Evidence: the packed artifact passed 110 commands across Oxlint 1.78.0 and 1.87.0, each with syntax-only and full tiers. In every consumer, one Oxlint run with only the matching rule enabled per file reported exactly one `tooling(<rule>)` finding on each of the 39 invalid files and nothing on the 39 valid ones; the composed config rejected `rikalabs(no-anemic-errors)` and `tooling(no-unknown-type-aliases)`; ESLint rejected `forEach(async ...)` and accepted `for...of`; the tarball carried NOTICE and the three license files. A scratch run of all 24 of Antidrift's cases for `no-calling-components-as-functions`, autofix output included, matched on both engines. Gates ran on Node 24.22.1 obtained through npx; this machine's default is Node 22. No publication.

## Two noisy rules ship off

`sql-template/no-unsafe-query` is off. It reports a template that opens with a SQL keyword and interpolates an identifier, call or member read, unless the tag is an identifier named `sql`. On 543 SQL-candidate files from BuilderIO/agent-native, cloudflare/agents, LibreChat and opencode it reported 1,540 templates, Antidrift's `no-sql-string-concat` 528. It reported 491 of Antidrift's 528, and 1,049 templates Antidrift proves safe: 864 untagged, such as constant table names and `?` placeholder lists, and 185 under tags that bind their values, 98 of them Cloudflare `this.sql`. Antidrift owns SQL templates while it is off.

`rikalabs/no-trivial-property-helpers` is off. Upstream 0.8.1 reports trivial helper definitions and also every call whose name matches `(get|read|extract|safe)(String|Number|Boolean|Prop|Value|Property)`, whatever the callee: on the same four repositories, 440 of its 449 reports were calls such as Monaco's `entry.model.getValue()` and a byte reader's `bb.readString()`. The 9 definition reports match what Antidrift's copy, which had dropped the call branch, reported. The rule has no option to drop that branch.

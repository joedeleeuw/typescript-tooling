## Ecosystem ownership and fallback policy

- Generic TypeScript and maintained plugin rules stay here rather than gaining Antidrift implementations. ESLint now enables `@typescript-eslint/no-explicit-any`; Oxlint loads the actual Unicorn plugin as `unicorn-js` because Oxlint 1.89 reserves the native plugin name and has no native `prefer-switch`. The switch rule uses `minimumCases: 4`.
- `@rikalabs/no-property-default-fallbacks` is the only Rika rule added and is off by default. `enforceNoPropertyDefaultFallbacks: true` opts into it without enabling Rika's aggressive preset. `propertyDefaultAllowedFiles` uses validated repository-relative suffix patterns because absolute override paths did not match in a packed consumer; suffix overrides worked. XAI's `mapUsage` and Arroxy's schema-error diagnostics are real intentional-default controls, so a global default would be too aggressive.
- Registry versions checked against npm: ESLint 10.13.0, Oxlint 1.89.0, oxlint-tsgolint 7.0.2005, TypeScript ESLint/parser 8.72.0, Unicorn 79.0.0, Rika 0.8.1, and @oxlint/plugins 1.89.0.
- Rebased onto upstream f0cffe1, retaining its baseline nested-ternary proof, packed-consumer cleanup, and formatting gate. No duplicate nested-ternary implementation remains.
- Oxlint 1.89 has no `react/react-compiler` rule. The supported replacement is the official `no-deriving-state-in-effects` rule from `eslint-plugin-react-hooks` 7.1.1 under `react-hooks-js`, preserving the `EffectDerivationsOfState` category. `enforceNoDerivedStateEffects` is an explicit opt-in, not a blanket compiler preset. A real derived-props-state case reports and a clean effect stays clean in the smoke and packed consumer.
